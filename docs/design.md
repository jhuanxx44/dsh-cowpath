# 设计摘要 — cowpath（弯路驱动的技能沉淀器）

> 权威设计源：me-wiki `wiki/projects/dsh-shortcut.md`。本文件是摘要与指针，**有歧义以 wiki 为准**。最后同步：2026-08-27。

## 定位

**不是「给 agent 加反思」，是只吃弯路、且必须过确定性门才能落地的技能沉淀器。**

## 术语

| 词 | 指什么 |
|---|---|
| trail | 原始执行轨迹（tool 名/参数/结果/报错/退出码），path 的原料 |
| path | 一条沉淀出来的 skill（走通过的路径） |
| herd | 跨会话聚合信号，多个会话独立走出同一条路 |
| paving | 过门后的落地动作 |

## 主循环

```text
完整执行轨迹（tool 名 / 参数 / 结果 / 报错 / 退出码）
  ↓
弯路配对（失败 → 修正 → 成功）      ── 无配对则丢弃，不蒸馏
  ↓
噪声过滤（环境类 / 瞬时自愈 / 对工具的负面断言）
  ↓
跨会话聚合（同签名命中 N 次 → 优先级排序）
  ↓
对比蒸馏（成败轨迹同时喂入）
  ↓
验证门（冻结任务集重放 + 非退化）    ── 退化则拒绝并回滚
  ↓
落地 + provenance
```

## 核心设计决定

1. **只收弯路，成对存**：错因签名与解法动作成对存；紧接着必须有噪声过滤（最坏一类是「对工具的负面断言」——会硬化成 agent 几个月后拒绝自己的理由）。规则先筛，不交给模型。
2. **频次是优先级**（⚠️ 2026-08-27 普查后建议修正为两段式，见 progress.md）：同一弯路被多个独立会话撞到说明不是偶然。
3. **验证器优先，且判定必须确定性**：验证器与生成器同构时自纠正可靠性急剧下降（幻觉壁垒）。lint 只做回归门，语义层人工抽检，不用 LLM 打分。
4. **防改尺子**：验证器自身的内容哈希参与可比性判断，改了 lint 规则就让旧基线失效。

## 交付物：三臂对比报告

| 臂 | 配置 | 回答什么 |
|---|---|---|
| A | 无 skill | 基线，任务本身有多难 |
| B | 人工手写 skill | 人写的上限 |
| C | 自进化 skill | 自动蒸馏能否接近或超过 B |

B 臂是关键不是陪衬——C 打不过 B，诚实结论就是「手写就够了」。

## 刻意不做

事实记忆层（有巨头且商业上集体证伪过）、设计 agent 的 agent（经济账 ~15,000 样本回本）、改自身代码/权重（实验室玩法）、embedding 路由（字面在这类区分上更准）、全量注入（线性膨胀 + 破坏 prefix cache）、压缩式摘要（信息保存优于压缩）。

## 第一步（当前所处阶段）

不先写插件。先手工跑 3–5 轮闭环：从真实会话里手挑弯路，人工写成 SKILL.md，跑 lint 门，记三臂数据。**验证「真实工作里到底有多少可识别的弯路」这个前提。** 验过之后按 观察层 → 弯路配对 → 门 → 蒸馏 的顺序实现，蒸馏放最后。

## 未决

- 验证域：me-wiki + lint（闭环立刻能转）vs 带测试套件的代码任务（验证器更强但要自攒任务集）。倾向前者起步。

## 2026-08-27 普查后的修正建议（待用户确认后写回 wiki）

1. 优先级信号改**两段式**：先确定性过滤（会话上下文噪声 → 自带修复指令 → 环境），剩余小池子再按频次 + 领域相关性排序
2. 弯路配对按**操作对象**（文件路径/目标）配对，不按 tool 名（agent 修正时换工具，按名配对会漏）
3. 噪声过滤第一层 = **会话上下文感知**（读 permission/sandbox/approval 元数据，session.jsonl 开头就有）
4. 自带修复指令类报错：错误文本即技能，免蒸馏（可旁路为 harness 级规则注入）

数据与证据：见 `progress.md`。
